# Пример: доменные события asterisk-connector

Конкретика одного проекта — как правила из SKILL.md выглядят на звонках. Правила общие, имена
и пути ниже — только этого проекта.

## Где что лежит

| Что | Где |
|---|---|
| Шина (тупой pub/sub, смысла не несёт) | `internal/events/topic.go` |
| Конструкторы событий и их инварианты | `internal/domain/events/` |
| Персистенция перехода | `incomingCallRepo` / `outboundCallRepo` |
| Продюсеры | хендлеры входящих и исходящих звонков |

Иммутабельный переход строится новым конструктором домена: хендлер входящего звонка собирает
`accepted`-копию через `NewIncomingCall`, а не мутирует существующую.

## Карта инвариантов по статусу звонка

Конструктор `New<Event>` требует от переданного звонка статус, соответствующий смыслу события.
Применять по смыслу, не механически.

| Событие | Требуемый `call.Status()` |
|---|---|
| `IncomingCallAppear` / `OutboundCallAppear` / `OutboundCallRequested` | `Pending` |
| `OperatorAcceptedCall` / `CallPreparedForOperator` / `OperatorJoinedCall` / `CallReadyForOperator` | `Accepted` |
| `ActiveCallAppear` / `OperatorActive` | `Active` |
| `CallEnded` | `Ended` |
| `CanceledCallAppear` | `Canceled` |

События, которые не фиксируют переход статуса, а несут транспорт (каналы в
`CallReadyForOperator`, SDP в `OperatorJoinedCall`), всё равно проверяют статус несущего звонка —
но дополнительных инвариантов на сам транспорт не навешивай без нужды.

## Известный баг, из которого выросло правило продюсера

**Статус сохранялся после публикации.** Отмену публиковали сразу, а вызов `SetCanceled` висел
отдельным подписчиком на `CanceledCallAppear`. В окне между публикацией и записью accept успевал
принять «мёртвый» звонок: событие об отмене уже разошлось, а в БД статус был ещё `pending`.

Починка — не ещё один подписчик, а перенос записи в продюсера, перед конструктором события:
transition → persist → construct → publish. Конструктор с проверкой статуса делает регресс
невозможным: событие просто не построится, пока звонок не переведён и не сохранён.

## Dual-write

Outbox в проекте нет: продюсер публикует в in-process шину после коммита, то есть событие с
внешним эффектом (деньги, вызов смежной системы) здесь пока класть некуда — сначала outbox.
