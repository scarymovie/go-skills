# Логирование: scarylog

## Правило

Логи в проекте пишутся через `scarylog` и только через него. Это относится и к коду,
который иначе взял бы `log/slog` напрямую, и к `log`, `fmt.Println` и любому стороннему
логгеру: разнобой в логгерах означает разный формат записи, и централизованный парсинг
на этом ломается.

`scarylog` — тонкая обёртка над `log/slog` без сторонних зависимостей. Она не заменяет
slog концептуально, а фиксирует одинаковые для всех сервисов решения: сигнатуру
`Error(err, ...)`, захват места вызова, группировку атрибутов, проброс логгера через
`context.Context`.

## Установка

```bash
go get github.com/scarymovie/scarylog/v2
```

```go
import "github.com/scarymovie/scarylog/v2"
```

HTTP-мидлварь лежит в подпакете и ставится тем же модулем:

```go
import "github.com/scarymovie/scarylog/v2/scaryhttp"
```

Конструктор и его опции, сигнатуры методов, `ErrorMsg` для стабильных сообщений под

**https://github.com/scarymovie/scarylog** → `SKILL.md`

вместе с библиотекой, и продублированное описание расходится с ней молча — читатель
узнаёт об этом, когда его код не собирается.

Отсюда же следует, куда нести правку: неточность в описании API исправляется **в
репозитории библиотеки**, а не здесь. В этом скилле уместны только правило выше и
установка.
