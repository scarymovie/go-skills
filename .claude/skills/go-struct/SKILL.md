# Go Structs: иммутабельный value object

Go 1.27 (минимум 1.26).

## Ключевые правила

1. **Поля — приватные** (`id`, не `ID`)
2. **Конструктор обязателен** — единственная точка входа, валидация только здесь
3. **Конструктор возвращает ошибку, а не паникует**: `(*T, error)` по умолчанию, `(T, error)` —
   по таблице ниже. Границы `panic` задаёт `go-code-style`; в этом скилле единственное
   легальное место для него — `Must*`-обёртка (ниже)
4. **Геттеры от значения** (`func (u User) ID() int`) — работают и с `User`, и с `*User`
5. **Обновление — новый конструктор**, не мутация на месте
6. **`With*` методы** — допустимы, но не приоритет

## Канонический пример

```go
import "fmt"

type User struct {
	id   int
	name string
}

// Конструктор — единственная точка входа
func NewUser(id int, name string) (*User, error) {
	if id <= 0 {
		return nil, fmt.Errorf("id must be positive: %d", id)
	}
	return &User{id: id, name: name}, nil
}

// Геттеры от значения — работают с User и *User
func (u User) ID() int      { return u.id }
func (u User) Name() string { return u.name }
```

```go
u, err := NewUser(1, "Rex")
if err != nil {
	return err
}

// "Обновление" — новый объект тем же конструктором, ошибка проверяется так же
u, err = NewUser(u.ID(), "новое имя")
if err != nil {
	return err
}
```

## Must-обёртка: единственное место для panic

Отделяет «плохой ввод» (ошибка конструктора) от «бага в коде» (паника), и без неё `error`
протекает в литералы.

```go
// MustNewUser — только для литералов, известных на этапе компиляции:
// тестовые фикстуры, статическая инициализация на старте до приёма трафика
func MustNewUser(id int, name string) *User {
	u, err := NewUser(id, name)
	if err != nil {
		panic(err)
	}
	return u
}
```

## Почему геттеры от значения

```go
type Animal interface {
	Name() string
}

type Dog struct{ name string }
type Cat struct{ name string }

func (d Dog) Name() string  { return d.name } // получатель — значение
func (c *Cat) Name() string { return c.name } // получатель — указатель

var _ Animal = Dog{}  // ок
var _ Animal = &Dog{} // ок
var _ Animal = &Cat{} // ок
// var _ Animal = Cat{} — не компилируется: Name() входит только в множество
// методов *Cat. По той же причине не компилируется NewCat().Name(), если
// NewCat возвращает Cat: временное значение не адресуемо
```

## Указатель vs значение из конструктора

| | `(User, error)` | `(*User, error)` |
|---|---|---|
| Где живёт | стек, пока значение не эскейпит | куча |
| Нагрузка на GC | нет, пока escape-анализ держит его на стеке | объект учитывается GC |
| Подходит для | горячий путь, маленькие структуры | доменные объекты, конфиги |
| Интерфейс | покрывается `User` и `*User` | покрывается только `*User` |

Возврат значения не гарантирует стек: запись в интерфейс, замыкание или поле по указателю
отправит его в кучу. Проверяй фактическое размещение через `go build -gcflags="-m"`.

### Опасность при указателях

```go
a, _ := NewUser(1, "Rex")
b := a // b держит тот же указатель

a, _ = NewUser(a.ID(), "новое имя")
// a — новый объект, а старый User{1, "Rex"} жив, пока жив b:
fmt.Println(a.Name(), b.Name()) // "новое имя Rex"
```

При высокой частоте обновлений — давление на GC.

## With* методы (допустимо, не приоритет)

Когда структура большая и нужно менять одно поле:

```go
func (u User) WithName(name string) User {
	u.name = name // u уже копия — receiver по значению
	return u
}
```

Получатель по значению — копия автоматически, иммутабельность снаружи не нарушена. Валидации
в `With*` нет, поэтому менять им можно только поля без инвариантов; остальное — через
конструктор, и тогда геттеры обязательны: без них нечем достать неизменяемые поля.

При добавлении поля в структуру места "частичного обновления" ищутся вручную: `User{id: 1}`
с именованными полями компилятор на пропущенные не ругает.

## Антипаттерны

```go
type Order struct {
	ID     int // публичное поле: снаружи соберут невалидное состояние в обход конструктора
	status string
}

// Сеттер — мутация на месте: прочитанное состояние объекта нельзя считать актуальным
func (o *Order) SetStatus(s string) { o.status = s }

// Геттер от указателя — ограничения с интерфейсами и адресуемостью
func (o *Order) Status() string { return o.status }
```

## Когда этот паттерн уместен

Доменные объекты, value objects, DTO между слоями — всё, где важна валидация при создании.
Не подходит структурам с десятками полей, где постоянно меняется одно поле: там `With*`
или мутабельный подход с мьютексом.
