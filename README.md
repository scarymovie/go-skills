# go-skills

Библиотека скиллов Claude Code с личными конвенциями по Go-сервисам: как раскладывать
проект, писать код и тесты, работать с PostgreSQL, описывать API, собирать образы и
искать проблемы в проде.

Скилл — это `SKILL.md`, который модель подгружает сама, когда запрос совпадает с его
`description`. Их не надо помнить и звать вручную: спросил «как написать миграцию» —
подтянулись конвенции миграций.

Версия — **Go 1.27**, ниже не поддерживается. Новый проект объявляет `go 1.27` в `go.mod`
сразу; существующий переводится на 1.27 (`go get go@1.27` и три команды следом — скилл
`go-quality`). Отдельных веток скиллов под старые версии нет и не планируется: при
`GOTOOLCHAIN=auto` тулчейн доезжает до нужной версии сам по директиве в `go.mod`, так что
поддерживать вилку было бы дороже, чем поднять версию.

Пометка версией у отдельных идиом (`wg.Go` — 1.25, `new(expr)` — 1.26) осталась: она
говорит, с какого релиза символ существует, и нужна при чтении чужого и старого кода.

## Как подключить

Скиллы ищутся в `.claude/skills/<имя>/SKILL.md` **на один уровень вглубь**. Вложенные
подкаталоги загрузчик не видит, поэтому область у доменных скиллов закодирована
префиксом имени.

```bash
# все скиллы в проект
cp -r go-skills/.claude/skills/* <проект>/.claude/skills/

# или выборочно
cp -r go-skills/.claude/skills/{go-code-style,go-testing,pgx-txmanager} <проект>/.claude/skills/
```

Автоматической раскатки нет — копии живут своей жизнью и расходятся. Если правишь
конвенцию, правь здесь, а в проекты переноси осознанно.

Личные скиллы (`~/.claude/skills/`) перекрывают проектные при совпадении имени.

## Общие скиллы

| Скилл | О чём |
|---|---|
| `go-project-structure` | Раскладка каталогов, слои, где объявлять интерфейсы репозиториев |
| `go-application-architecture` | main.go, структура Application, связывание зависимостей, Run/Shutdown, HTTP-стек |
| `go-code-style` | Ошибки и их обёртывание, единое правило про panic, горутины, современные идиомы |
| `go-struct` | Приватные поля, конструктор как единственная точка входа, иммутабельность |
| `go-file-size-limit` | Пороги размера файла и по чему его делить |
| `go-config` | Конфиг одним YAML вместо env: типизация, строгий декодер, валидация на старте |
| `go-quality` | fmt, модернизаторы go fix, vet, golangci-lint, govulncheck, флаги релизной сборки |
| `go-testing` | Выбор вида теста, изоляция на реальном Postgres, детерминизм, конкурентность |
| `go-profiling` | pprof и его защита, flight recorder, бенчмарки, PGO, поиск утечек |
| `go-scarylog` | Логгер проекта вместо голого slog: правило и установка. **Описание API — в репозитории библиотеки** |
| `pgx-txmanager` | pgxpool, устойчивый старт, транзакции и propagation, классификация ошибок, CopyFrom |
| `postgres-migrations` | Свой мигратор и парные `*.up.sql`/`*.down.sql`, типы колонок, constraint'ы, и блокировки, из-за которых миграция роняет прод |
| `go-events` | Контракт доменного события, порядок продюсера, dual-write и outbox |
| `eventbus` | Как писать свою in-process шину: actor-модель, типизированный фасад, backpressure |
| `workerpool` | Как писать свой пул горутин: инварианты, shutdown с force-stop, panic recovery |
| `openapi-rpc-conventions` | RPC-over-HTTP: только POST, именование схем, единый формат ошибки |
| `openapi-codegen` | Настройка oapi-codegen v2, std-http + strict server, раскладка сгенерированного кода |
| `docker-go` | Multi-stage сборка, кеши BuildKit, выбор рантайм-базы, Compose |

## Доменные скиллы

Применимы, только когда в проекте есть соответствующая технология.

| Скилл | О чём |
|---|---|
| `telephony-sip-diagnostics` | Почему рвётся звонок: валидация 200 OK, SDP, NAT-регистрация через rport |
| `telephony-realtime-audio` | RTP/WebRTC-мост: размер буфера, потери по sequence number, порядок shutdown |
| `websocket-openapi-guidelines` | WebSocket-контракт в OpenAPI: конверт сообщения, фиктивный эндпоинт для кодогена |
| `address-fias-index` | **Проектный, не конвенция.** Схема подсистемы адресов platform-integrator |

`address-fias-index` описывает таблицы и миграции конкретного репозитория и протухает
с очередной миграцией. За пределами своего проекта он не просто бесполезен, а вреден —
подключай только туда, где эта схема есть.

## Устройство скилла

- `SKILL.md` — решения и ловушки. Читается целиком при срабатывании триггера, поэтому
  держится коротким.
- `references/*.md` — длинные справочники и примеры, на которые ссылается SKILL.md.
  Модель открывает их по надобности, а не всегда.
- `name` во frontmatter — только ярлык в списке; имя команды берётся из имени каталога.
- `description` и `when_to_use` вместе обрезаются на 1536 символах.
